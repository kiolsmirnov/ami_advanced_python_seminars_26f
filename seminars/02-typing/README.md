# Семинар 2 — Типы

По лекции 2. Теории минимум, весь семинар — про одно: **mypy находит
баги, которых не видно, пока код не упадёт у пользователя.**

## Что здесь

| Файл | Что это |
|---|---|
| [`seminar.ipynb`](seminar.ipynb) | 4 раздела, ~45 минут |
| [`task/README.md`](task/README.md) | условие задачи |
| [`task/gradebook.py`](task/gradebook.py) | модуль с шестью багами |
| [`task/check_typing.py`](task/check_typing.py) | автопроверка |

## Разделы

1. **Читаем ошибки mypy** — пять сообщений, которые встретятся в задаче
2. **Protocol** — утиная типизация, которую видит проверяльщик
3. **`list[Dog]` против `Sequence[Dog]`** — вопрос с мок-интервью
4. **`Any` и `type: ignore`** — живой контраст: обычный mypy молчит,
   `--strict` находит

Каждый раздел заканчивается багом, который есть в задаче. Ничего лишнего
внутри нет.

## Задача

`task/gradebook.py` импортируется, `pytest` зелёный — и в нём шесть багов.

```
mypy  (обычный)  → 5 ошибок
mypy --strict    → 7 ошибок
```

Студент читает вывод mypy и чинит код. Заглушить через `# type: ignore`,
`cast` или `Any` не выйдет — верификатор проверяет это отдельно.

```bash
make check-typing
```

## Как запустить

```bash
uv sync
make nb          # JupyterLab → seminars/02-typing/seminar.ipynb
```

Ноутбук без выводов, запускай ячейки сверху вниз: первая создаёт
песочницу и функцию `mypy()`, последняя песочницу удаляет.
